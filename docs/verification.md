## Что проверяют браузерные тесты

Консультация с источником, создание диалога, форма с согласием, лид в CRM, горячий приоритет по намерению, изменение стадии с повторной загрузкой страницы, передача оператору и доставка ответа в исходный чат. Аналитика проверяется сравнением счётчиков до и после новой заявки. CSV проверяется по HTTP-статусу и содержимому. CRUD материалов проходит создание, изменение и удаление. На ширине 390 px проверяется отсутствие переполнения документа у лендинга, чата и основных страниц CRM.

В API проверены отказ без сессии, неизвестный токен диалога, превышение длины сообщения и отказ сохранять контакт без согласия. Модульные тесты проверяют квалификацию, локальный поиск, CSV injection, отказ от подмены инструкций, fallback ИИ при сбое, отклонение выдуманного ответа, HMAC webhook и запись ошибки внешней доставки.

## Границы проверки

Рабочие ключи внешних сервисов не использовались. Telegram Bot API и реальный ИИ-провайдер не проверялись end-to-end; поведение провайдера и webhook проверено с HTTP-mock. Google Sheets реализован как подготовка строк и CSV, без прямого API-вызова. Публичный сервер не развёрнут: настроенная сессия Vercel и облачная PostgreSQL не обнаружены. Нагрузочного и независимого security-аудита не было.

Публичный demo-вход предназначен для общей песочницы. Перед рабочим запуском нужны закрытая авторизация, политика обработки данных, роли и долговечные очереди интеграций. Основной репозиторий портфолио не изменялся.
